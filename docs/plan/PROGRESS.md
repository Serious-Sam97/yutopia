## Map structure upgrade (2026-10-10)
Maps are now **per-space data** (`yutopia_spaces.layout`, null = the built-in Studio Building), edited in build mode. One set of rules in `packages/shared/src/map-edit.ts` + `grid.ts` serves the client preview and the server.
1. **Walls:** Walls tool paints walls, any floor finish, or empty space by click-drag. Refused (with a reason): walling over furniture, people, doors or the arrival point, or removing the wall a board/screen hangs on.
2. **Rooms & desks for a person:** Rooms tool — drag a rectangle → name, owner (project members), sound (private/open/booth), floor, optional walls + door built around it. A sign over the door shows "ROOM · Owner". Desks tool — click any seat to give it to someone: they always land there; a nameplate shows on it (one assigned desk per person).
3. **Doors:** placed in a one-tile gap between walls; open / closed (swings open as people pass) / locked. Only the room's owner locks/unlocks (project owners can unlock in an emergency); **while locked only the owner can walk in or out** — enforced server-side per person (each person has their own walk grid), and pathfinding, teleport and "join them" respect it.
4. **Map size:** presets S 32×24 · M 48×36 · L 64×48 · XL 80×60 · XXL 96×72 or custom 16–96; resize keeps content top-left (furniture beyond the edge removed), or start blank; set the arrival point.
- Yondra: migration `2026_10_12_000001_add_layout_to_yutopia_spaces`, signed `PUT /internal/yutopia/spaces/{id}/layout` (shape-validated), `GET /api/yutopia/spaces/{id}/members`; seeder adds the **Yutopia Lab** sandbox project.
- Tests: shared +5 (painting guards, resize, blank, rooms + locked doors), world-server +3 (paint permissions, owned room + lock incl. a tampered client pushing into the doorway, desks + resize), backend +1, e2e `map-edit.spec.ts` (blank map → room with owner → walls → desk → lock → Bia kept out → resize).

## Third person — demo (2026-10-13, ask: "third person mode" as an option per player)

## Game room — sound and lag fixes (2026-10-15, asks: "no volume on modal", "volume cropping (sometimes on snes)", "second player with a lot of lag and input lag 1-2 seconds")
- **The host's volume.** The core plays straight to the host's speakers, so neither the TV's knob nor the *TV & video* setting reached whoever ran the game. `emu.ts` now reroutes whatever the core connects to its speakers through a gain (`Emu.volume`, set every frame in `GameRoom.hostVolume`: hearing from where you stand × 0.9 × `prefs.vol.tv` × the TV's knob — what everyone else hears from the TV); the tap for the TV stream stays raw, so viewers keep their own volume. The console's panel shows its TV's knob under the picture (`TvVolume` with `v.tv`), as the TV's panel did.
- **Sound cropping.** RetroArch's web audio driver fills a buffer from the page's own frame loop (`audio_latency`, was 64 ms for every core): a main-thread hitch longer than that is a gap you hear, and the 16-bit cores leave the least margin while the host also draws the world and sends the TV out. Per core now (`AUDIO_LATENCY`): 2600 / 8-bit / handheld 80 ms, 16-bit 128 ms, 16-bit black 112 ms.
- **Pad 2's lag.** Measured with two Chromium windows on the stack (scratch spec, deleted): pad 2 → world-server → host **4–20 ms**, host's picture **17–37 ms** after, the viewer's TV **100–300 ms** after the host — but the TV went out at **1280 × 960**: RetroArch sizes its canvas from the CSS box × the real device-pixel ratio (its ResizeObserver reads `devicePixelContentBoxSize`), so on a 2× screen the 640 px box was four times the pixels to encode (top layer 1.4 Mbps), send and decode. `startEmu` now watches the canvas's device-pixel box and sizes the CSS box so the picture stays 640 × 480 whatever the screen (or an emulated ratio) says; the top layer is capped at 1 Mbps. After: the viewer's TV **18–47 ms** after the host, the video jitter buffer 8 ms (was 30), audio 30 ms (was 60–75), `f` layer 640 wide. On a real link this is the difference between a few hundred ms and seconds on a slow uplink or a phone's decoder.
- **Kept off screen on purpose:** the emulator canvas must stay off screen (`left: -10000px`): once a WebGL canvas is composited, Chrome clears its drawing buffer after each frame and reading it back (the TV's picture, the glow's colour, the e2e) gives black — tried a clipped on-screen holder for Firefox's sake, every game test went black.
